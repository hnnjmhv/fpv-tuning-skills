# 原项目评估与改进

[English](assessment.en.md)

## 评估结论

原版本是有用的离线原型：已找到解码器 CLI，能够读取部分黑盒头、计算频谱并输出配置文件。但分析和参数决策耦合过紧，存在足以影响结论的缺陷，不适合以“全自动调好 PID/滤波”的保证对外发布。新版定位为可追溯的分析、联合候选方案和复飞验证技能。

## 主要发现

| 风险 | 原实现位置 | 影响 | 新版处理 |
| --- | --- | --- | --- |
| 不连续采样拼接做频谱 | `throttle_noise`、稳定段布尔筛选 | 产生边界跳变，可能制造假高频能量 | 连续时间窗内估谱，再按油门/杆量汇总 |
| 无时间列默认 1000Hz | `sample_rate`、`time_info` | 横轴和噪声频带可能整体错误 | 要求显式时间单位，检查时间间隔与缺口 |
| debug 当作 D-term、axisP 当作 setpoint | 早期 `find_axis_columns` 前缀回退 | 跟随误差和 D 噪声失真 | 严格按字段角色读取，缺失标记未知 |
| 反卷积输出尾部强制归一 | `response_analysis` | 人为构造单位稳态增益，过冲百分比不可靠 | 仅保留诊断性 coherence，不自动推导 D |
| 低 coherence 固定门槛直接加 D | `recommend` | 中低质量响应被当作实飞证据 | 数据测量与候选决策分开，候选必须引用证据 |
| D-term 固定 RMS 判断安全 | `classify_noise` | 忽略 gain、TPA、采样与机型差异 | 报告频带、单位与工况，不输出普适安全阈值 |
| 电机范围由观测峰值猜测 | `motor_metrics` | 低油门 DShot 可被误读成 PWM | 使用 `motorOutput`；未知边界不报饱和百分比 |
| 配置多 profile 平铺合并 | `parse_cli_config` | 把另一个 PID profile 的值写到当前机体 | 显式选择 0 起始 CLI profile，拒绝配置/日志不一致 |
| 枚举数值解释错误 | 历史完整 CLI | `iterm_relax_type=1` 实为 SETPOINT，却写成 GYRO | 按固定版本源码映射，并有回归测试 |
| 以不同飞行整体百分比作因果解释 | `compare_rounds` 与人工总结 | 误把动作、电池、风或姿态差异归给参数 | 匹配油门/杆量分层，明确只报告观察性差异 |
| 机体 Z 被称作垂直振荡 | `throttle_transient_metrics` 与报告 | 推力/姿态变化被误诊为高度抖动 | 标记 body-Z，缺姿态变换时不宣称地面系运动 |
| RPM 配置等同于遥测正常 | 旧建议规则 | 缺少有效遥测和 DShot 错误证据 | 配置、字段覆盖、错误率、频谱效果分开记录 |
| 两轮限制与单次模式冲突 | `--rounds`、`--one-shot`、报告模板 | 单次模式仍写“两轮”，同日志可重复 | 默认三次日志指纹检查，另支持单次完整方案 |
| 低证据状态仍自动改变多类参数 | `recommend` | 给出精确数值却无法确定改动依据 | 生成候选而非安全保证；记录理由、证据、回滚与未覆盖项 |
| 绑定个人路径、未定义依赖 | 旧 SKILL 示例 | 换机器无法运行 | Python 包、相对入口、安装器、跨平台 CI |

## 对历史调参结论的修正

“Pitch 过冲从 38% 降到 5.7% 证明 D 有效”和“body-Z 振荡增加 33% 说明放宽滤波过头”都是超过原方法能力的表述。旧曲线、未匹配的飞行和机体加速度不足以证明这些因果。历史数值方案应视为未验证候选，不能作为公开预设或新机型默认值。

本次发布不重新为旧日志给出实飞机体参数，也不修改飞控。代码回归与实飞验收是不同工作：测试通过只证明相应程序行为，不能证明候选参数适合某架机。

## 新版交付

- 中文 `$穿越机调参` 与英文 `$fpv-drone-tuning` 两个入口，共用同一 Python 引擎。
- 三次实际飞行检测；每次同时审查完整 PID/滤波/控制设置。
- 逐字段单位、连续时间窗、日志指纹、解码器版本/哈希、可分析频带与缺失项。
- 完整已知配置、实际差异、对应回滚，以及尚未实飞验证的明确状态。
- 默认不发布日志、GPS、机体配置、个人路径或第三方二进制。

研究依据见 [research.md](research.md)，实现限制见 [methodology.md](methodology.md)。
